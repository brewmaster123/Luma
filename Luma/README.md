# Luma 0.4.2 (6)

Полный исходный проект iPhone + Apple Watch. Основа — 0.4.1 с исправлениями экрана часов и идентификатором com.sevchlenko.luma.

Будильники, REM-подсказки и общая проба iPhone снова используют обычные локальные уведомления. Каждый звук конечный, без зацикливания и без команды ручной остановки: мелодия 4/8/15 секунд либо собственный голос/импорт до 28 секунд. Окончание уведомления не зависит от работающего таймера Luma. В Silent Mode звук не проходит; уведомление может быть ограничено настройками Focus или перенаправлено на часы.

Перед началом/возобновлением REM и сохранением/включением будильника со звуком iPhone появляется короткая памятка: выключить беззвучный режим, включить «Сон», разрешить в нём Luma. Кнопка открывает настройки уведомлений Luma. Публичного перехода прямо в исключения Focus не найдено; путь указан в памятке. Автоматически менять Silent/Focus приложение не пытается.

При установке поверх предыдущей версии Luma сначала отменяет свои старые AlarmKit-будильники. Новые через AlarmKit не создаются. Импорт, локальный голосовой дневник, авторский текст справки, Manrope, широкие области нажатия и сортировка сохранены. Для двух устройств возвращена отдельная конечная серия Watch; системное перенаправление требует проверки на ваших устройствах.

## Запуск

Прочитайте Luma-START.md в корне архива. Откройте Luma.xcodeproj, выберите прежнюю Team для обеих целей. Не меняйте bundle ID и не удаляйте установленную копию для обновления. Минимумы — iOS 17 / watchOS 10; для очистки старого AlarmKit используйте сборку Xcode 26+. Готовый workflow находится в корне архива и в Docs/ios-build.yml.

## Проверено

51 XCTest ядра, включая сохранение данных при миграции; синтаксис Swift; 91 структурная проверка; браузерный макет в пяти размерах и десяти сценариях. Подробности — [VALIDATION](Docs/VALIDATION.md). Xcode, iOS/watchOS SDK, GitHub Actions и реальные устройства этой версии здесь не запускались. [Проверка на устройствах](Docs/DEVICE-TESTS.md).

Непрерывная ночная телеметрия Watch и точность REM не подтверждены. Наличие конечного уведомления не решает доступность свежих датчиков и выполнение алгоритма в фоне. Сохранённых будильников может быть сколько угодно; в системную очередь попадают ближайшие, её обновляет открытие Luma.
