# Luma 0.5.0 (8)

Основа — финальный Luma-iPhone-AppleWatch-v0.4.3-Interface.zip, SHA256 fff300e1f69f3a297f9acc8d9bad98a1399d3528c61db44e3838532d29edbf55. Старые журналы, звуки, кириллический Manrope, экран Watch с исправленными зонами нажатия и bundle prefix сохранены.

- В режиме «iPhone + Watch» добавлен прямой конечный AVAudioPlayer телефона для будильника, REM и общей пробы. Часы получают отдельную серию; общая целевая дата используется для REM и пробы. Голос/импорт до 28 секунд, numberOfLoops = 0.
- Для заблокированного телефона требуется явно запущенный реальный микрофонный сеанс. Готовность проверяет свежие входные данные и AVAudioEngine, а не только флаг. Прерывание ставит сеанс на паузу; устаревшие callbacks не восстанавливают статус.
- Обычный резерв совместного будильника перенесён на +5 секунд. Окно живого плеера 0…2 секунды. Принятый запуск + сохранение ID предшествуют отмене резерва. Ошибка оставляет резерв. Позднее открытие не переигрывает старый сигнал, сохранённый ID не повторяется, изменения/удаление проверяются перед запуском.
- WirePacket v2 получил необязательное cueDate; старые пакеты читаются. Ошибка sendMessageData сообщается отдельно. Устаревшая проба отменяется поколением; Watch передаёт replyTo в ответе.
- Памятка учитывает конкретный маршрут черновика будильника. Для обоих устройств объясняет громкость мультимедиа, явный микрофонный сеанс, Focus и резерв. В Night появился краткий статус микрофона при совместных сигналах.
- Сохранены «Осознанные Сновидения и Выход из Тела», авторская справка REM, местные голосовые заметки, импорт, интервалы 3/8/12 секунд и остальные UI-правки.

Проверено 59 XCTest ядра, 92 структурные проверки, синтаксис Sources и HTML-макет. Это не нативная сборка и не доказательство реальной одновременной доставки ночью. Условия и протокол — NOTIFICATION-ROUTING.md и DEVICE-TESTS.md. AlarmKit не планирует сигналы; алгоритм REM и доступность Watch всю ночь этим обновлением не исправляются.
