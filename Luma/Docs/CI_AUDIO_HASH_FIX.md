# CI: контрольные суммы и аудио — 0.9.4 (20)

## Наблюдения по скриншоту

Проверки проекта, очереди и сборка iPhone прошли. Две ошибки остановили упаковку IPA:

1. Raw SHA-256 не совпал для проекта, схемы, project-graph.json, queue-harness и двух сервисов.
2. AVFoundation вывел предупреждение о non-interleaved file settings, затем renderer сообщил «Не удалось обработать короткий звук»; необработанный throw из Swift main завершил процесс с exit 132.

Core XCTest был пропущен из-за более раннего сбоя. Ни упаковка, ни установка не подтверждены.

## Контрольные суммы

Все семь перечисленных файлов локальной основы содержат CRLF, в четырёх есть только одна строка CRLF среди LF. Старый манифест хешировал эти байты. При checkout с LF те же исходники получают другой raw hash.

[Git gitattributes](https://git-scm.com/docs/gitattributes) документирует нормализацию строк текста. В новой версии:

- .gitattributes задаёт LF для текстовых форматов и отключает преобразование бинарных.
- Xcode generator явно пишет UTF-8/LF на Windows и macOS.
- Schema 2 манифеста задаёт `lf-text` или `raw` каждому файлу. В текстовом режиме заменяется только CRLF → LF; пробелы, BOM, UTF-8 байты и код не фильтруются.
- Ожидаемые хеши построены из основы 0.9.3, а намеренно изменённые файлы перечислены отдельно.
- 13 Python-тестов проверяют переносимость и отказ при настоящем изменении. Полный сохранённый набор копируется с LF и CRLF и проверяется повторно.
- Исторические версии продолжают проверяться по raw SHA-256 без нормализации или записи в них.

Проверка не удалена и не переведена в continue-on-error.

## AVFoundation

Формат файла и формат рабочих буферов — разные параметры. [AVAudioFile initializer](https://developer.apple.com/documentation/avfaudio/avaudiofile/init(forwriting:settings:commonformat:interleaved:)) принимает их раздельно. [int16ChannelData](https://developer.apple.com/documentation/avfaudio/avaudiopcmbuffer/int16channeldata) доступен только для соответствующего типа samples в buffer, а не просто из-за PCM16 на диске.

В старом render guard были объединены длина чтения и наличие Int16 pointer, поэтому по скриншоту нельзя точно установить, какая часть guard отказала. Новый путь убирает обе предпосылки:

- Импорт, затухание и проверка используют Float32 non-interleaved.
- Файл сохраняется по явным параметрам Linear PCM16, mono, 22 050 Гц, interleaved disk layout.
- Renderer накапливает 88 200 frames из чтений по 4096; нулевое чтение до конца — отдельная ошибка с журналом.
- Начало/конец сглаживаются, короткое содержимое дополняется тишиной, оригинал не меняется.
- Версия кэша — v3.
- Тестовые WAV создаются с отдельными параметрами файла. Принудительного раскрытия Int16 pointer больше нет.
- Main теста обрабатывает ошибку и возвращает 1, не скрывая неуспех за fatal top-level throw.

Native matrix: Float32 stereo 48 kHz и PCM16 mono 22.05 kHz, каждый с 0,32 / 2 / 4 / 40 сек. Проверяются формат файла, 88 200 frames, fade, padding, cache и неизменность исходника, отдельно invalid input.

## Статус

Python-тесты и переносимые проверки выполнены. Новая AVFoundation matrix и Xcode build здесь не запускались: среда Windows. Следующий GitHub run должен подтвердить native результат. Зелёная компиляция предыдущей ревизии не считается таким подтверждением. Физическая длительность сигнала всё ещё требует iPhone.

IPA упаковывается только при успешных preserved/core/audio/queue/iphone шагах; core теперь запускается для диагностики и после сбоя preserved. Ни один обязательный результат не обходится.
