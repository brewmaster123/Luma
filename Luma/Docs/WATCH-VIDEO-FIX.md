# Разбор двух видео и внесённые исправления

В video3.mp4 примерно на 19-й секунде показан ответ Luma «Дождитесь окончания текущей пробы». Ранее меняется статус на «REM остановлен на часах». Это подтверждает, что обработчики нажатий выполнялись. По видео нельзя утверждать, что сенсорный экран или все кнопки были заблокированы.

В прежнем коде успешный запрос уведомлений никак не отражался на экране. HealthKit тоже мог завершать запрос без новой формы, а затем ждать включения фоновой доставки. Проба имела внутренний флаг isPlaying, который экран не наблюдал. Постоянная кнопка остановки не объясняла, есть ли сеанс, и не предлагала восстановить остановленное наблюдение.

Исправлены обратная связь, последовательность операций, область нажатия и управление паузой. Для HealthKit показано «Запрос обработан», а не «Доступ разрешён»: Apple не раскрывает приложению факт разрешения чтения. Не добавлены обход разрешений, фиктивные измерения или автоматическое согласие пользователя.

В video.mp4 видны Failed Registering Bundle Identifier и No profiles для com.example.luma. Установлен общий идентификатор com.sevchlenko.luma по точному написанию из сообщения пользователя. На видео итоговое написание нового идентификатора не подтверждается; перед установкой поверх другой копии оно должно совпадать с её действительным bundle ID. Случайная генерация ID при каждой сборке не используется.

Xcode всё ещё требует выбранную команду разработчика и действующую подпись. Конкретный Team ID из имени аккаунта не выводится. При выборе другой команды уже зарегистрированный ID может быть недоступен ей.
