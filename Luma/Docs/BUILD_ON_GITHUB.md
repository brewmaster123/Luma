# Как собрать 0.9.9 на GitHub

0.9.9 (28) на GitHub ещё не собиралась. Собирает пользователь сам. Агент может подготовить ветку локально, но публикует её только пользователь, в GitHub Desktop. У git из командной строки на этом компьютере нет входа в GitHub, а MCP к Google Chrome не используется (указание пользователя).

0.9.8 (27) собиралась 17 ноября 2026: ветка `luma/0.9.8-lumenoir`, коммит `30ea0d5`, запуск https://github.com/brewmaster123/Luma/actions/runs/44076006890 — зелёный с первого раза.

## Что отправлять

Содержимое папки `V.0.9.9` целиком: папки `.github` и `Luma`, файлы `.gitignore`, `.gitattributes` и документы рядом с ними. Служебные папки (`Luma/.validation-tools`, `Luma/.build`, `build-logs`, `dist`) в репозиторий не попадают — они перечислены в `.gitignore`.

## Шаги в GitHub Desktop

1. Сделать новую копию репозитория (Clone) **внутри** `V.0.9.9\Luma\.validation-tools\`, например в папку `ci-repo`. Не использовать копии из `V.0.9.6`, `V.0.9.7` и `V.0.9.8`: любые действия GitHub Desktop меняют служебные файлы в этих папках.
2. В этой копии создать ветку от `luma/0.9.8-lumenoir`, имя должно начинаться с `luma/`, например `luma/0.9.9-forest`.
3. Удалить из копии всё, кроме папки `.git`, и скопировать в неё содержимое `V.0.9.9` (кроме `Luma\.validation-tools` и `Luma\.build`).
4. Commit, затем Publish branch / Push.
5. На сайте GitHub: Actions → запуск «Lumenoir 0.9.9 - living sheets, sounds, melodies, forest settings» начнётся сам после отправки ветки `luma/...`. Его можно запустить и вручную кнопкой Run workflow.
6. После зелёной галочки внизу страницы запуска, в Artifacts, скачать `Luma-0.9.9-unsigned-zip`. Внутри — `Luma-unsigned.ipa`. Подписывать и ставить прежним способом.

## Что делает сборка

1. Проверка структуры проекта. Сюда входят формат, тишина по краям и громкость трёх мелодий Lumenoir.
2. Сохранность:
   - файлы, не менявшиеся с 0.9.6;
   - файлы, не менявшиеся с 0.9.7 (механизм сигналов);
   - `AppModel.swift` — ровно в том виде, в каком записаны три добавления 0.9.9.
3. Полнота английского перевода.
4. Тесты ядра (`swift test`).
5. Проверка импорта звука и проверка очереди сигналов на Mac.
6. Сборка приложения для iPhone и для Apple Watch.
7. Упаковка IPA. Она выполняется, только если всё предыдущее прошло, версия в приложении — 0.9.9 (28) и в Luma.app есть три файла мелодий.

## Если сборка красная

Код 0.9.9 на этом компьютере не компилировался: здесь нет компилятора Swift. Его прочитали независимые проверяющие, но ошибки компиляции на шаге «Build iPhone app» всё равно возможны. В этом случае откройте упавший шаг, скопируйте строки с `error:` и передайте агенту — он исправит в `V.0.9.9`. Журналы сборки также лежат в Artifacts под именем `Luma-build-logs`.

Не обходить проверки ради IPA.
