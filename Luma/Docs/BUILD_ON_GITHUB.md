# Как собрать 0.9.8 на GitHub

17 ноября 2026 пользователь поручил агенту собрать готовую 0.9.8 и отдельно разрешил отправить исходники и технические документы в brewmaster123/Luma, ветку luma/0.9.8-lumenoir, включая необходимые исправления CI и итоговые отчёты. Сборка отправлена через GitHub Desktop из отдельного checkout внутри V.0.9.8. Инструкции ниже остаются способом ручной сборки.

Результат: коммит `30ea0d5`, запуск https://github.com/brewmaster123/Luma/actions/runs/44076006890 — зелёный с первого раза (16:39–16:48). В Artifacts лежат `Luma-unsigned.ipa` (сам IPA, 10,9 МБ), `Luma-0.9.8-unsigned-zip` (тот же IPA в ZIP) и `Luma-build-logs`; хранятся 7 дней. У git из командной строки на этом компьютере нет входа в GitHub, поэтому отправку делают в GitHub Desktop.

## Что отправлять

Содержимое папки `V.0.9.8` целиком: папки `.github` и `Luma`, файлы `.gitignore`, `.gitattributes` и документы рядом с ними. Служебные папки (`Luma/.validation-tools`, `Luma/.build`, `build-logs`, `dist`) в репозиторий не попадают — они перечислены в `.gitignore`.

## Шаги в GitHub Desktop

1. Сделать новую копию репозитория (Clone) **внутри** `V.0.9.8\Luma\.validation-tools\`, например в папку `ci-repo`. Не использовать копии, лежащие в `V.0.9.6` и `V.0.9.7`: любые действия GitHub Desktop меняют служебные файлы в этих папках.
2. В этой копии создать ветку, имя которой начинается с `luma/`, например `luma/0.9.8-atelier`.
3. Удалить из копии всё, кроме папки `.git`, и скопировать в неё содержимое `V.0.9.8` (кроме `Luma\.validation-tools` и `Luma\.build`).
4. Commit, затем Publish branch / Push.
5. На сайте GitHub: Actions → запуск «Luma 0.9.8 - Atelier design, English, 3-20 s signal» начнётся сам после отправки ветки `luma/...`. Его можно запустить и вручную кнопкой Run workflow.
6. После зелёной галочки внизу страницы запуска, в Artifacts, скачать `Luma-0.9.8-unsigned-zip`. Внутри — `Luma-unsigned.ipa`. Подписывать и ставить прежним способом.

## Что делает сборка

1. Проверка структуры проекта.
2. Сохранность: файлы, не менявшиеся с 0.9.6, и файлы, не менявшиеся с 0.9.7 (весь механизм сигналов).
3. Полнота английского перевода.
4. 130 тестов ядра (`swift test`).
5. Проверка импорта звука и проверка очереди сигналов на Mac.
6. Сборка приложения для iPhone и для Apple Watch.
7. Упаковка IPA. Она выполняется только если всё предыдущее прошло, а версия в приложении — 0.9.8 (27).

## Если сборка красная

Новый код экранов на этом компьютере не компилировался: здесь нет компилятора Swift. Ошибки компиляции на шаге «Build iPhone app» возможны. В этом случае: открыть упавший шаг, скопировать строки с `error:` и передать агенту — он исправит в `V.0.9.8`. Журналы сборки также лежат в Artifacts под именем `Luma-build-logs`.

Не обходить проверки ради IPA.
