# Длительность сигнала: 0.9.7 (23)

Настройки → «Сигнал будильника» → «Длительность сигнала»: целое значение 3–10, default 4. Один параметр применяется к smart, indirect и probe. Изменение действует на будущие события, включая уже поставленные в очередь; сигнал в пределах секунды до начала и уже начавшийся не изменяется.

## Сохранение прежнего механизма

PCM-файл и builder остались четырёхсекундными, бит в бит как в эталоне. Отдельный срок Stop хранится в записи события, а не вычисляется из момента получения alarmUpdates. Для 3 секунд Stop прерывает WAV раньше конца; для 5–10 секунд AlarmKit может повторять тот же WAV до Stop. Полностью сохраняется зависимость от реально работающего NightAudio при блокировке; пауза фонового дождя сначала снимает очередь. Watch-расписание и его системный звук не меняются этой настройкой.

Каждая запись хранит абсолютный срок fireAt + stopDurationSeconds. Изменение настройки переписывает только будущие локальные записи; UUID, fireAt, soundName и дата отсчёта непрямого метода остаются прежними. При успешной записи старые deadline Task отменяются и создаются заново. При ошибке ledger откатывается в памяти, старые таймеры не меняются, UserDefaults не обновляется.

После interruption аудио получает deadline активного события напрямую из ledger даже во время подготовки очереди. Длительность ограниченного окна восстановления — max(8, remaining + 4), где remaining ограничен 0–10 сек; lease на 2 сек больше. Для исходного срока 4 остаётся 8/10, для 10 — до 14/16. Это не планировщик запуска suspended/terminated процесса.

## Совместимость и резервная копия

Предпочтение записывается в UserDefaults `luma.alarmkit.signal-duration.v1`. AppArchive/LumaState/LocalStore не менялись. В schema-3 alarms.json добавляется optional `stopAfterSeconds`. Старые записи без ключа читаются как 4; значения вне диапазона также дают 4. 0.9.6 игнорирует неизвестный ключ и снова использует 4.

Перед первой перезаписью существующего ledger его исходные байты атомарно сохраняются в Application Support/LumaAlarmKit/alarms-before-duration-setting.json. Существующая копия никогда не заменяется; её содержимое — записи AlarmKit, не дневник или исходные аудио. На iOS сохраняется защита completeUntilFirstUserAuthentication.

Перед установкой старой IPA сначала остановить ночной режим и снять системные сигналы в текущей Luma. 0.9.6 откроет совместимые данные и вернётся к 4 секундам. Резервный ledger служит для контролируемого восстановления после снятия системной очереди; не копировать его поверх живого ledger с другим набором UUID. Системную резервную копию данных iPhone создавать отдельно.

## Проверка

Новые core cases: диапазон/default, deadline каждого значения, позднее обновление, чтение старой записи, round-trip, invalid value, старый decoder, пределы interruption. Native harness: все режимы без новых UUID, relaunch, смена через reconcile, активные 10 секунд, неизменность копии, ошибка записи, in-flight edit, фактическая замена Task в обе стороны.

Результаты Windows и macOS разделяются в verification.json. Подтверждение пользователем 0.9.6 не является тестом нового диапазона. Проверки новых 3/10 секунд на устройстве: DEVICE_TESTS.md.
