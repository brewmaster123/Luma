# Luma 0.4.2 — проверка перед ночным использованием

Начните с дневной пробы. Установите поверх той же копии (та же Team и bundle ID), откройте обе части, проверьте строку Luma 0.4.2 (6). В этом пакете нет подтверждённого результата Xcode или физических устройств.

## До поездки к Mac

Загрузите весь обновлённый проект в GitHub, включая Luma.xcodeproj, новые Swift-файлы и workflow из архива. Запустите Actions: Test and build Luma. Должны пройти Core tests, Audio import, Watch build и iPhone build. Это проверит Apple SDK компиляцию, но не реальные нажатия или доставку. При красном шаге сохраните лог со строками error: до поездки.

## Экран Apple Watch — первые пять минут

1. На часах кнопки нажимаются всей карточкой, включая свободное место справа от надписи. Скролл свободный.
2. «Проба сигнала»: прогресс, конечная серия, затем «Проба завершена». Во время пробы та же кнопка останавливает её. Повторная проба после окончания доступна. Выход из Luma останавливает foreground-пробу.
3. «Разрешить уведомления»: новый запрос или показ уже существующего статуса. При ранее выбранном отказе не ожидайте повторной системной формы. На iPhone откройте Watch → Уведомления → Luma и включите доставку.
4. «Разрешить данные сна»: ответьте в форме часов. Статус «Запрос обработан» не доказывает разрешение чтения. На iPhone: Здоровье → профиль → Приложения → Luma → пульс, дыхание, сон.
5. Несколько быстрых нажатий не запускают параллельные permission-запросы. После ответа spinner исчезает. Ошибка фоновых обновлений Health не блокирует пробу и остальные кнопки.
6. Начните ночь на iPhone. Часы подтверждают сеанс, кнопка «Приостановить на часах» сменяется «Возобновить на часах»; быстрая пауза/возобновление не перемешивает операции. После завершения ночи на iPhone кнопок паузы/возобновления нет.

## Памятка

- Начните REM с телефонным звуком, затем закройте памятку: сеанс не должен начаться.
- Создайте/измените время, нажмите «Сохранить», закройте памятку: время в черновике сохранено, будильник ещё не изменён.
- Откройте настройки кнопкой. Откроются уведомления именно Luma. Вернитесь, выберите «Продолжить»: действие должно выполниться один раз.
- Повторите при отказе в разрешении, выключенном «Звуки» и после их разрешения. Ошибка должна быть понятной, без ложного успешного включения.
- Watch-only не показывает требование отключить Silent на телефоне.

## Звук и доставка

| Сценарий | Что проверить |
|---|---|
| Обычная мелодия 4/8/15 секунд | Каждый сигнал звучит один раз и затихает без нажатия. |
| Записанный голос; импорт короткого и длинного файла | Выбранный файл слышен; длинный импорт ограничен первыми 28 секундами; повторного запуска дорожки нет. |
| iPhone заблокирован, Luma в фоне | Поставленный будильник доставлен; звук заканчивается без выполнения кода приложения. |
| iPhone в Silent Mode | Звука обычного уведомления быть не должно. Это ожидаемое ограничение. |
| Silent выключен, Focus «Сон», Luma разрешена | Уведомление Luma допускается настройками; проверить ненулевую громкость, «Звуки» и немедленную доставку. |
| Возврат из настроек за секунду до будильника | Уже ожидающий запрос не исчезает при обновлении очереди. |
| Редактирование/выключение/удаление | Старое будущее время не звучит; новое планируется один раз. |
| Повтор по дням | Следующие дни отдельными конечными звуками; открывайте Luma для пополнения очереди. |
| Только Watch; оба устройства | Своя конечная серия часов доставляется; нет неожиданного дополнительного зеркального сигнала. Проверить с заблокированным iPhone и часами на руке. |
| Микрофон включён во время сигнала | Слышно уведомление; после него продолжается реальный анализ. Собственная мелодия не создаёт новый REM-эпизод. |

Обычные уведомления iPhone могут уходить на Apple Watch вместо телефона; фактическое поведение зависит от состояния блокировки и зеркалирования. Проверка foreground-пробы на часах сама по себе не подтверждает ночные уведомления.

## Обновление поверх AlarmKit

В старой версии поставьте будущий разовый и повторяющийся будильник. Обновите с тем же ID, откройте новую Luma. Старые AlarmKit-записи должны быть отменены, а соответствующие будущие настройки — поставлены как уведомления. Проверьте также вариант с ранее отозванным разрешением AlarmKit: приложение не должно скрывать проблему или дублировать звонок. Журнал, голосовые заметки и выбранные мелодии остаются.

## REM

Дневной будильник проверяет доставку, а не REM-алгоритм. Ночью отдельно фиксируйте доступность свежих датчиков, время эпизодов, паузы, фактические сигналы. Отсутствие свежих данных должно приводить к пропуску, а не выдуманному срабатыванию. Принудительное закрытие может прекратить вычисление новых REM-подсказок, хотя уже поставленные уведомления обслуживает система.
