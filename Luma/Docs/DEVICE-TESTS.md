Сейчас все пункты ниже имеют статус **не выполнено**. Наличие кода теста или предполагаемое поведение Apple API не считается успешным испытанием.

Перед испытаниями записать модель iPhone, модель Apple Watch, версии ОС/Xcode, тип профиля подписи, уровень заряда, состояние Bluetooth/Wi-Fi, бесшумного режима и фокусирования. Для первого теста достаточно дневного сценария.

## Отмена и сбои

| Проверка | Ожидаемый результат |
|---|---|
| Отмена на часах | Ожидающие запросы удалены |
| Отмена на iPhone при связи | Статус отмены появляется после квитанции часов |
| Отмена на iPhone без связи | Показывается ожидание; локальная сессия на часах не объявляется отменённой |
| Позднее восстановление связи | Команды обрабатываются в правильном порядке; старый arm не возвращает отменённую сессию |
| Один пакет через несколько каналов WatchConnectivity | Одна серия, повторная квитанция |
| Сбой после записи резерва, до завершения планирования | Нет повторной серии; неполная подготовка отменена при восстановлении |
| Частичная ошибка добавления уведомлений | Уже добавленные запросы этой попытки удалены |
| Команда приходит после выбранного времени | Отказ без внезапной серии и скрытого переноса |
| Изменение часового пояса / DST | Время и дата плана понятны; нет внезапного повторного запуска |

## Данные, REM и история

| Проверка | Ожидаемый результат |
|---|---|
| Нет свежего пульса/движения | «Недостаточно данных», отсутствие REM-серии |
| Один образец перечитан несколько раз | Не создаётся искусственный устойчивый REM-признак |
| Большие пробелы или несколько источников | Не создаётся искусственно плотный ряд |
| Возврат после долгого пребывания в фоне | Требуется новый участок свежих данных |
| Окно 20/30 минут закончилось | Никаких новых сигналов этой сессии |
| Утром открыть часы, затем iPhone | Доставленные уведомления считываются до очистки завершённой серии |
| Удалённое пользователем уведомление | Неизвестная доставка не превращается в доказанное попадание |
| История Apple отсутствует/противоречива | Нет утверждения о подтверждённом REM |
| Дневник и экспорт | Текст сохраняется после перезапуска; JSON соответствует своим записям |

Ночные наблюдения сначала должны измерить доступность фоновых данных. Если свежих отрезков недостаточно, эта архитектура REM не проходит проверку: увеличение числа ночей или ослабление порогов не заменяет решение проблемы доступа к датчикам. Нужны изменения архитектуры и повторная проверка.

## Интерфейс

На маленьком и большом iPhone проверить прокрутку, основную кнопку и карточку выбора сигналов. Проверить крупные размеры Dynamic Type, VoiceOver, контраст на низкой яркости, отсутствие обрезанного текста на маленьких Apple Watch. Не давать тестируемому подсказок: попросить подготовить три сигнала, отменить их и записать сон.

## Перед публикацией

Нативная сборка и испытания должны пройти; главный REM-сценарий должен соответствовать заявленному поведению; точность должна иметь независимую оценку или обещания точности должны отсутствовать. Затем нужны проверка подписи/entitlements, privacy manifest и App Privacy по фактической версии, публичная политика конфиденциальности, скриншоты с устройств, проверка рабочего имени и App Review. В этой поставке эти действия не выполнены.
