# Luma 0.5.0 (8) — дневная проверка на iPhone и Watch

Установите обе части поверх прежней копии с той же Team и bundle ID. Не удаляйте приложение с локальными заметками. На обоих экранах проверьте 0.5.0 (8). Перед поездкой к Mac запустите включённый GitHub workflow: core tests, audio import, Watch build и iPhone build должны завершиться успешно. Здесь эта Apple SDK сборка и испытания устройств не выполнялись.

## Первые пять минут на Watch

1. Проверьте нажатие по всей карточке, в том числе справа от текста, и прокрутку.
2. «Проба сигнала»: конечная серия, прогресс, затем «Проба завершена». Повторите; во время повторной пробы остановите той же кнопкой. Выход из приложения часов прекращает foreground-пробу.
3. «Разрешить уведомления»: новый запрос либо точный статус уже сделанного выбора. Отказ не обязан вызывать системную форму повторно. Настройки меняются через Watch на iPhone → Уведомления → Luma.
4. «Разрешить данные сна»: ответьте в форме. Статус «Запрос обработан» не доказывает, что чтение разрешено. На iPhone: Здоровье → профиль → Приложения → Luma → пульс, дыхание, сон.
5. Несколько быстрых нажатий не запускают параллельные запросы. Spinner исчезает после ответа. Ошибка фоновых обновлений Health не блокирует кнопки пробы.
6. Начните сеанс на телефоне, проверьте паузу/возобновление Watch. Завершите на iPhone и убедитесь, что старый сеанс больше нельзя возобновить на часах.

## Совместный сигнал — основной тест

1. Выберите «Часы + микрофон» и «iPhone + Watch». Отключите наушники, поднимите громкость мультимедиа. Для резервных уведомлений выключите Silent, включите звуки Luma и разрешите её в Focus «Сон».
2. С открытой Luma на обоих устройствах выполните общую пробу телефона. Звук iPhone и серия Watch должны начаться близко по времени и закончиться сами. После окончания проба снова доступна. Повторите с личной голосовой дорожкой.
3. Поставьте будильник через 2–3 минуты с выбором «iPhone + Watch» именно в его редакторе. Дождитесь подтверждения настроек часов. Затем начните ночь и дождитесь «Микрофон активен · звук iPhone напрямую».
4. Наденьте часы, заблокируйте телефон и погасите экран Watch. В назначенное время проверьте звук телефона и серию часов. Отсчитайте ещё минимум 10 секунд после конца: повторной мелодии и дополнительного резервного уведомления быть не должно при успешном плеере. Допустимая задержка запуска телефона — до 2 секунд; точная синхронизация не обещается.
5. Откройте iPhone через минуту: старый сигнал не должен звучать снова. Повторите отдельный будильник с коротким и длинным импортом; длинный файл ограничен первыми 28 секундами.
6. Не делайте вывода о ночной надёжности по единственной foreground-пробе. Повторите на заблокированных устройствах после 20–30 минут настоящего анализа микрофона и с включённым Focus «Сон».

## Отказы и отмена

| Проверка | Ожидаемое поведение |
|---|---|
| Закрыть памятку начала ночи | Сеанс не начинается; микрофон не включается. |
| Источник только Watch, маршрут обоих | REM не начинается скрыто с микрофоном; предложен явный выбор «Часы + микрофон». |
| Отказ в микрофоне | Понятная ошибка, нет статуса активного анализа. |
| Звонок / прерывание микрофона | Ночной сеанс ставится на паузу; статус готовности исчезает. Для продолжения нужен явный запуск. |
| Завершить сеанс во время разрешений возобновления | Старый сеанс не возвращается в running после закрытия системной формы. |
| Сохранить совместный будильник без начала ночи, заблокировать iPhone | Резервное обычное уведомление примерно через 5 секунд после времени. Оно может уйти на Watch; оба устройства не обещаются. |
| Принудительно закрыть Luma после постановки очереди | Плеер не выполняется, резерв остаётся системным уведомлением. После позднего открытия звук не догоняется. |
| Громкость мультимедиа 0 | Плеер не считается успешно запущенным; для будильника остаётся резерв. |
| Удалить, выключить, изменить время/звук будильника | Старая очередь отменяется, устаревшее вхождение не запускает плеер. |
| Возврат в Luma рядом со временем сигнала | Обновление очереди не переигрывает уже доставленное уведомление и не создаёт второй плеер. |
| Два будильника на одну секунду | Одновременно второй плеер не запускается. Если первый ещё играет, второй остаётся резервным уведомлением. |

При резком прерывании уже начатого звука он может закончиться раньше; ранее отменённый резерв не восстанавливается. Резерв может зеркалироваться на Watch дополнительно к собственной серии — это видно только на устройствах.

## Остальные режимы и данные

«Только iPhone» остаётся обычным конечным уведомлением; Silent его заглушает, Apple может направить его на Watch. «Только Watch» не запускает отдельный плеер iPhone. Проверьте сортировку будильников, широкое нажатие на время, запись/проигрывание голосовых заметок в обоих разделах дневника. Старые заметки и выбранные мелодии должны остаться после обновления.

## REM ночью

Совместный дневной будильник проверяет доставку, а не REM. Для новых REM-подсказок Watch требуется доступное приложение часов: отправка iPhone не будит его из приостановленного состояния. Фиксируйте свежесть датчиков, время оценки, результаты iPhone и ответ Watch, фактический сигнал. Опоздавшие сообщения пропускаются. При нехватке данных REM не должен выдумываться. Работу всю ночь и точность нужно исследовать отдельно.

## Обновление поверх AlarmKit

При обновлении с прежней AlarmKit-версии откройте новую Luma с тем же ID, чтобы отменить её старые системные будильники. Ошибка очистки не должна скрываться или оставлять новый дублирующий звонок. На чистой установке новой авторизации AlarmKit нет.
