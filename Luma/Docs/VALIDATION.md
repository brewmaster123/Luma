# Luma 0.2 — выполненная проверка

Дата: 8 сентября 2026. Среда разработки — Linux; Xcode и устройства Apple недоступны.

| Проверка | Результат | Что это подтверждает |
|---|---|---|
| Компиляция LumaCore | Успешно, Swift 6.0.3, режим языка Swift 5 | Типы и код платформонезависимого ядра |
| XCTest | 31 сценарий, 0 ошибок: 18 новых + 13 прежних | Планирование, конечные серии, память эпизодов, защитные правила, звук, миграция, настройка |
| Нативные исходники iOS/watchOS | `swiftc -frontend -parse` успешно для обеих целей | Синтаксис, без проверки Apple SDK |
| Координатор AppModel | Дополнительная проверка типов с локальными заглушками сервисов | Обычные Swift-типы и обе условные ветки; не настоящие API Apple |
| Структура проекта | 73 проверки | Разбор реального pbxproj, 2 цели, файлы/схемы, принадлежность исходников, plist, ресурсы, мелодии, шрифты |
| GitHub Actions | YAML разобран; все run-блоки прошли `bash -n` | Синтаксис workflow и shell, не фактическая облачная сборка |
| HTML | `node --check`, Playwright + Chromium 152, 12 проверок | Основные действия, сохранение, конечная проба и узкий экран |
| Дизайн | PNG осмотрен; нет горизонтального переполнения на 375 px | Браузерный макет, не снимок SwiftUI-приложения |
| Нативная сборка Xcode | Не выполнена | Требуется запуск приложенного workflow |
| Подпись и установка | Не выполнены | IPA здесь не создавался и не подписывался |
| Ночной сбор датчиков и физические сигналы | Не проверены | Требуются реальные iPhone и Apple Watch |
| REM-точность, эффективность настройки | Не измерены | Нужны размеченные независимые исследования сна |

XCTest действительно исполнялся, а не проверялся поиском названий методов. На Linux использована прямая компиляция LumaCore в модуль/библиотеку и настоящий XCTest runner со всеми методами из `Tests/LumaCoreTests`; команды Package Manager в этой среде могут падать на недоступной статистике `/proc`. При повторной проверке также наблюдался сбой запуска Linux runtime; следующий запуск того же кода успешно выполнил все 31 тест. Итоговый журнал `core-tests.log` содержит полный успешный результат. Это ограничение среды не заменяет штатный `swift test` на Mac; workflow запускает именно его.

Новые проверки включают 12 часов одного непрерывного эпизода без повторов; 20 отдельных эпизодов с восстановлением из JSON; пропадание данных, короткий выход, cooldown и повторение одного timestamp; 1000 сохранённых будильников и 48 ближайших событий; истёкшие одноразовые события, выключенные будильники и DST; три маршрута; старую запись дневника; тишину, периодический синтетический звук, повреждённые и загрязнённые окна; запрет незаметного fallback с комбинированного режима; opt-in, 12 независимых ночей, ограничение влияния и неоднозначность отклика.

12 проверок макета: создание отдельного будильника, сохранение после перезагрузки, предупреждение без выдуманных процентов, каждый из трёх маршрутов, автоматическое окончание пробы, сохранение отклика, экранирование текста сна, недоступность будущего толкования, отсутствие переполнения на 375 px, отсутствие ошибок JavaScript. Реальный микрофон браузера и физический звук/Watch не проверялись.

`static-checks.json` описывает только структурный скрипт: его поля `swift_compiled: false` и `xctest_executed: false` относятся к этому скрипту. Фактический запуск Swift и XCTest описан отдельно выше и в журнале.

Из архива исключены локальный Linux toolchain, временные заглушки, бинарники тестов, браузер и служебные данные проверки. На Mac достаточно `swift test` и Xcode; прямую компиляцию Linux повторять не нужно.
