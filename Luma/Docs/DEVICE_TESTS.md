# Физические тесты 0.9.2 (18)

**Все сценарии ниже требуют физического iPhone. Ни один здесь не выполнен.** Грамматика, static checks, подставная очередь и наличие WAV не являются физической проверкой.

## Подготовка и критерий

Установить поверх 0.9.1 с прежним bundle ID/Team. Открыть Luma и убедиться, что миграция не сообщает об оставшихся AlarmKit alarms. Разрешить уведомления, звуки, баннеры и экран блокировки, выключить Silent, разрешить Luma в Focus, отключить сводку для Luma. Сначала тестировать без Watch.

Использовать базовую мелодию Luma. Записать звук внешним телефоном/рекордером, не записью микрофона Luma: она может менять аудиосессию и мешать тесту suspension. Время в интерфейсе и JSONL не доказывает работу динамика.

Для каждого события записать плановое и слышимое начало, слышимый конец, длительность, повторы, состояние экрана/процесса, iOS build, модель iPhone/Watch, Silent/Focus, громкость, Bluetooth/наушники, результат и ссылку на внешнюю запись. Рабочий ориентир: конечный ресурс 4,000 с, измеренное окно около четырёх секунд с указанной погрешностью; отсутствие позднего повтора проверять минимум ещё 60 секунд. Не объявлять допуск платформенной гарантией.

Для suspension/force quit важны реальные умный будильник и 30-минутная серия. Проба через 60 секунд — дополнительная быстрая проверка, не замена ночного теста.

Если ранее установлен старый самостоятельный Watch-клиент, его собственная очередь не управляется iPhone-веткой 0.9.1/0.9.2. Перед испытанием исключить старую Watch-очередь через прежнее приложение/настройки; не считать её сигналом новой версии.

## Диагностика

В «Настройки → Журнал проверки» доступен `Application Support/LumaAlarmKit/finite-cue-events.jsonl`; OSLog category `finite-cues`.

- `schedule_attempt` / `schedule_accepted`: попытка и наличие запроса в системной очереди.
- `sound_prepare_failed`, `schedule_failed_or_cancelled`: подготовка/постановка не удалась.
- `reservation_recovered` / `future_request_missing`: восстановление после прерванного await или потеря будущего запроса.
- `legacy_alarmkit_cancel_attempt` / `legacy_alarmkit_cancel_failed` / `legacy_alarmkit_empty_verified`: миграция старого AlarmKit.
- `cancel_attempt` / `cancel_verified` / `queue_cancel_verified`: отмена будущих запросов; уже начавшийся звук может закончиться естественно.
- `foreground_presentation_requested`: запрос показать/озвучить foreground уведомление, не акустическое начало.
- `system_delivery_observed` / `due_request_no_longer_pending`: сведения о доставке/исчезновении, не измерение EOF.
- `unexpected_request_configuration`, `orphan_requests_cancelled`: неожиданная конфигурация или потерянный ID.

У обычного уведомления нет callback фактического конца звука в suspended приложении. Не создавать ложные `stop_succeeded` через таймер. Повтор одного аудиофайла системой может быть обнаружен только внешней записью. Для выпуска приложить заполненную матрицу, результаты macOS CI и записи нескольких последовательных сигналов.
