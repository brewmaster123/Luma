# Архитектура и пределы версии 0.1

## Сигналы

Авторитетное состояние сессии хранится на Apple Watch. iPhone отправляет команду с уникальным идентификатором, сохраняет ожидание и получает квитанцию. Используются WatchConnectivity application context, user info transfer и сообщение при доступной живой связи. Повторная доставка одного пакета не должна создавать новую серию: часы сохраняют квитанцию и возвращают её повторно. Устаревшие команды отклоняются.

Отмена с телефона остаётся ожидающей до ответа часов. Если часы не на связи, сессию можно отменить на самих часах. Отмена не отзывается автоматически после тайм-аута телефона.

`CueEngine` создаёт стабильные идентификаторы уведомлений по UUID плана и индексу. Все сигналы должны целиком помещаться в заданное окно. Опоздавшая команда режима «По времени» отклоняется, без немедленного сигнала и без скрытого переноса на следующий день. Перед добавлением уведомлений сохраняется резерв серии. После сбоя приложение предпочитает пропустить серию, а не повторить её.

`UNTimeIntervalNotificationTrigger` всегда имеет `repeats: false`. Пользователю не требуется нажимать кнопку остановки; звуковое/тактильное оповещение уведомления ограничено системой. Рисунок, реальное число физических постукиваний, доставка при заблокированных/снятых часах, фокусирование и группировка принадлежат watchOS. Это обязательные проверки на устройствах. [Документация UserNotifications](https://developer.apple.com/documentation/usernotifications).

Тактильная проба `FiniteHaptics` содержит конечный цикл по допустимому числу сигналов. При переходе приложения в фон цикл отменяется. Выбранная пауза 8/12/20 секунд применяется к ночным уведомлениям; для короткой пользовательской пробы используется 1,5 секунды.

## Данные и предварительная оценка

`HealthService` читает пульс за последний час и стадии сна за последние 36 часов. В расчёт принимаются записи с признаками происхождения от Apple Watch. Пользовательские записи пульса исключаются. Источники не смешиваются в одну искусственно плотную временную последовательность. HealthKit не позволяет достоверно отличить отказ в чтении от отсутствия данных; интерфейс этого не утверждает.

HealthKit observer запрашивает фоновую доставку с частотой `.hourly`. Это не таймер реального времени и не гарантия пробуждения процесса. Уведомления observer корректно завершаются вызовом completion handler. Свежие стадии Apple через этот путь во время сна не получаются. [Ответ Apple](https://developer.apple.com/forums/thread/804512), [HKObserverQuery](https://developer.apple.com/documentation/healthkit/hkobserverquery).

`MotionService` использует Core Motion при активном приложении на часах и останавливается при уходе в фон. RMS пользовательского ускорения собирается в 30-секундные отрезки. Это не всенощный регистратор и не получение движения в обход watchOS.

`REMEstimator` — ручные, непроверенные правила для оценки возможности дальнейшей разработки. Они рассматривают 12 минут последних измерений и предшествующий участок в пределах 45 минут, изменения медианного пульса, разброс пульса и низкую двигательную активность. Разброс редких значений BPM **не является HRV** и в интерфейсе так не называется. Порог 0,72 — инженерный параметр, не 72% вероятности.

Расчёт требует свежего пульса, достаточной плотности одной последовательности и неперекрывающихся свежих отрезков движения. Нет движения в данных — не значит, что человек неподвижен. Повторное чтение одного образца не продлевает подтверждение. Для серии нужны новые подходящие образцы на протяжении как минимум 120 секунд, без большого перерыва между оценками.

В текущем жизненном цикле после погашения экрана движение перестаёт обновляться. Поэтому условие REM ночью, как правило, не будет подтверждаться. Версию нельзя рекламировать как работающий всенощный REM-будильник. Требуется отдельный этап разработки допустимого фонового наблюдения и модели на данных реальных ночей.

Не используются фиктивные тренировки, бесшумное аудио для удержания процесса или приватные API. Smart Alarm extended runtime рассчитан на ограниченные сессии и имеет особые правила тактильного оповещения; он не заменён здесь недокументированным бесконечным фоновым выполнением. [Extended runtime sessions](https://developer.apple.com/documentation/watchkit/using-extended-runtime-sessions).

## История и оценка попадания

Запланированное время не считается доказательством доставки. Только сведения `UNUserNotificationCenter` меняют запись на `deliveryObserved`. Если уведомление было удалено до повторного открытия приложения или система не дала сведения о доставке, результат остаётся неизвестным.

При запуске сведения о доставленных уведомлениях читаются до удаления завершённой серии. Утреннее сопоставление использует фактическое время уведомления, если оно известно. Конфликтующие стадии или отсутствие разметки дают `unknown`.

Совпадение с историей Apple — согласие двух алгоритмов. Это не оценка точности относительно полисомнографии. Для будущей валидации следует раздельно измерять:

1. долю сигналов, попавших в независимо размеченный REM;
2. долю REM-эпизодов, в которых приложение успело подать сигнал;
3. задержку сигнала и долю окон, пропущенных из-за нехватки данных;
4. надёжность доставки уведомлений и субъективную заметность;
5. отдельно — сообщения об осознанных сновидениях, не выводя их из датчиков.

Не следует считать общей accuracy долю правильно определённых не-REM отрезков: такое число может быть высоким при полном отсутствии полезных REM-сигналов. Публикации о готовом классификаторе Apple не дают процента точности этому коду. Пример независимой работы о потребительских устройствах: [Sensors 2024, 24(20), 6532](https://www.mdpi.com/1424-8220/24/20/6532).

## Локальное хранение

Состояние записывается атомарно в Application Support, с защитой файла до первой аутентификации после запуска устройства. Каталог исключён из резервного копирования. Повреждённое или несовместимое хранилище не сбрасывается молча; включение сессии блокируется. После ошибки чтения на часах ожидающие уведомления Luma отменяются при запуске.

Записи дневника остаются на iPhone. Между парными устройствами передаются планы, состояния и записи уведомлений; сырые измерения пульса и текст дневника не пересылаются нашим WatchConnectivity протоколом. Передачи на сервер разработчика нет. Отдельные системные настройки синхронизации «Здоровья» принадлежат Apple.

История сигналов ограничена 30 днями. Дневник остаётся до удаления. Экспорт JSON выполняется только явным действием пользователя. Экспорт содержит состояние приложения и журнал сигналов; он не выгружает сырые измерения HealthKit. Удаление истории действует локально и не удаляет данные из приложения «Здоровье» или со второго устройства; при последующей синхронизации записи сигналов часов могут появиться снова.

## Сборка

Общее ядро одновременно входит в два native target и доступно как отдельная Swift Package для тестов. Для проекта Xcode не требуется импорт бинарной библиотеки LumaCore: общие Swift-файлы компилируются в каждый target. Scheme `Luma` встраивает watchOS application; оба приложения имеют отдельные Info.plist и entitlements.

`scripts/generate_project.py` воспроизводит проект без XcodeGen. После ручного изменения project.pbxproj генератор перезапишет такие изменения; обычному пользователю запускать его не нужно. Скрипт `check-on-mac.sh` сначала запускает SwiftPM tests, затем две сборки для симуляторов. App Store archive и подпись выполняются в Xcode отдельно.
