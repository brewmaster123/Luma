# Luma 0.9.7 (23)

Настройки → «Сигнал будильника» → «Длительность сигнала»: от 3 до 10 секунд с шагом 1 секунда. По умолчанию 4 секунды. Настройка общая для умного будильника, непрямого метода и обеих проб AlarmKit; сохраняется после закрытия приложения.

Основа — подтверждённая пользователем эталонная 0.9.6 (22). V.0.9.6 и Baselines/V.0.9.6 не изменяются. Все файлы этой разработки, инструменты и сборки находятся в V.0.9.7.

Сохраняется прежний механизм: реальный тихий ночной дождь обеспечивает выполнение Luma после блокировки; заранее заведённый Stop останавливает конкретный AlarmKit UUID в срок `fireAt + выбранные секунды`. Четырёхсекундный WAV, обработка пользовательских записей и механизм Watch оставлены прежними. При сроке больше четырёх секунд AlarmKit может повторить этот WAV до Stop.

Изменение настройки обновляет только будущие локальные сроки Stop, без удаления и повторной постановки системных будильников. Сигнал, уже начавшийся или ожидаемый в ближайшую секунду, сохраняет свой прежний срок. Даты серии и идентификаторы не сдвигаются. Настройка не меняет длительность системного звука уведомлений Apple Watch.

Bundle ID `com.sevchlenko.luma` и прежняя команда подписи сохранены. Дневник, исходные записи, AppArchive/LocalStore и планировщики не меняются. Сведения о совместимости и возврате: [SIGNAL_DURATION.md](Luma/Docs/SIGNAL_DURATION.md).

Локальные проверки прошли. Нативная проверка Xcode и новая IPA пока ожидаются: см. [DEVELOPMENT_STATUS.md](DEVELOPMENT_STATUS.md). Результат 0.9.6 не выдаётся за тест 0.9.7. Для нового диапазона нужны пробы 3/4/10 секунд на заблокированном и разблокированном iPhone.

На Mac с Xcode 26: `cd Luma`, затем `bash scripts/check-on-mac.sh`. CI включает сохранность исходников, XCTest, AVFoundation, интеграционные проверки очереди и сборки iPhone/Watch. IPA выпускается только после всех обязательных проверок.
