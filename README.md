# Luma 0.9.2 (18)

Продолжение Luma 0.9.1 (17). Полный Xcode-проект, ресурсы и workflow находятся в этой папке. Предыдущие версии не изменяются.

## Исправление и статус

Умный будильник и непрямой метод используют **обычные локальные уведомления с конечным звуком длиной 4,0 секунды**. Каждое событие имеет отдельный ID и `repeats: false`; серия продолжается по своему расписанию. Звук заканчивается вместе с файлом, без Stop из процесса Luma.

В 0.9.1 четырёхсекундный CAF уже существовал. Остановка AlarmKit зависела от исполняющегося приложения: `Task.sleep`, опрос и `alarmUpdates` не обеспечивают исполнение после приостановки iOS. Короткий файл не является документированным способом завершить AlarmKit.

**Это кандидат для физической проверки.** Xcode-сборка 0.9.2, исполнение Swift XCTest, AVFoundation и queue-harness на macOS, а также измерение звука на iPhone здесь не выполнялись. Переносимые проверки не подтверждают работу на устройстве.

## Условия слышимого сигнала

- Разрешить Luma уведомления, звуки, баннеры и экран блокировки.
- Выключить беззвучный режим; установить подходящую громкость звонка и уведомлений.
- Разрешить Luma в нужном Focus, включая «Сон». Убрать Luma из сводки уведомлений.
- При подключённых Watch проверить маршрут: уведомление может прийти на часы вместо заблокированного iPhone. Для проверки звука iPhone отключить отражение Luma в настройках Watch и выполнить физический тест.
- После перезагрузки сначала разблокировать iPhone: копии звука используют защиту до первого входа.

Обычные уведомления не обеспечивают обход Silent/Focus или одновременный сигнал iPhone + Watch. iOS может задержать, заглушить или прервать звук. Совокупность «ровно четыре секунды, всегда вовремя, на iPhone, в любом режиме» публичными API здесь не гарантируется. Выбор сделан в пользу конечного звука без ручного выключения.

## Обновление с 0.9.1

Установить поверх прежнего приложения с bundle ID **`com.sevchlenko.luma`** и прежней командой подписи. Не удалять приложение, если нужно сохранить данные.

1. Открыть Luma после установки, до ночи.
2. Миграция отменяет все AlarmKit-будильники приложения, включая потерянные ID, и проверяет пустую очередь. Старые локальные очереди также очищаются.
3. Если отмена не подтверждена, новая очередь не ставится. Вернуть прежнее разрешение на будильники в настройках iPhone и повторно открыть Luma.
4. Прочитать обновлённую настройку коротких сигналов и разрешить уведомления. Старое согласие на AlarmKit не переносится на другое поведение.
5. Экран «Включить сохранённые сигналы» восстанавливает будущие будильники и исходный отсчёт непрямого метода. Если экран закрыт, открыть «Настройки → Как настроить ночные сигналы → Разрешить сигналы».
6. Выполнить пробу с блокировкой через 60 секунд, затем серию с интервалом 30 минут.

Сохраняются ID пользовательских будильников, время, дни недели, начало интервального сеанса, голоса, дневник и отклики. Системные ID при переходе с AlarmKit заменяются после отмены старых. Пропущенные события не проигрываются задним числом.

## Очередь и звук

До 60 ближайших запросов; учитываются другие ожидающие уведомления приложения в пределах бюджета 64. Непрямой метод планируется в пределах 12 часов: при 30 минутах это до 24 событий, при 10 минутах — максимум 60 событий за 10 часов до пополнения. Другие будильники разделяют бюджет. Конец поставленного интервального расписания показан в справке.

Пополнение происходит при открытии/возобновлении Luma и пока процесс исполняется. Бесконечная серия после исчерпания очереди не обещается.

Базовый `Luma/Resources/luma-tone-4.wav` сохранён из основы: PCM16, mono, 22 050 Гц, 88 200 отсчётов, плавное начало и окончание. Он включён в Resources build phase. Пользовательский звук преобразуется в отдельный `Library/Sounds/luma-cue4-<SHA256>.caf` с затуханием 120 мс. Оригинал не обрезается. Короткий исходник дополняется тишиной; его слышимая часть может быть короче четырёх секунд. Старый кэш AlarmKit не используется.

## Сборка на Mac и установка

Нужны Xcode 26+ и iOS SDK 26+ для availability-gated отмены старого AlarmKit. Workflow сохраняет Xcode 26.3. Deployment target — iOS 17+. watchOS target уже отсутствовал в 0.9.1.

```bash
cd Luma
python3 scripts/check-static.py
swift test
bash scripts/check-audio-on-mac.sh
bash scripts/check-finite-queue-on-mac.sh
bash scripts/check-on-mac.sh
```

Последняя команда повторяет проверки и собирает Simulator target. Для установки открыть `Luma/Luma.xcodeproj`, выбрать схему `Luma`, прежний Development Team и физический iPhone, затем Run.

`CODE_SIGN_STYLE = Automatic`, bundle ID и HealthKit entitlement сохранены. Приватные сертификаты, provisioning profile и Development Team в переданной основе не найдены; они не создавались и не подменялись.

Для IPA: Product → Archive → Distribute App с доступным способом подписи. Для CLI-экспорта использовать прежний профиль и соответствующий ему `ExportOptions.plist`. Новый подписанный или unsigned IPA здесь не получен.

## GitHub Actions

Сохранён `.github/workflows/ios-build.yml`. Ожидаемый корень репозитория — **содержимое V.0.9.2**, рядом лежат `.github` и `Luma`. При загрузке всех исторических папок в один репозиторий вложенный workflow сам не активируется.

Workflow проверяет структуру, запускает core XCTest, AVFoundation и 19 сценариев очереди с подставным адаптером, компилирует iPhone target и упаковывает `dist/Luma-unsigned.ipa`. Все проверки обязательны. После провала XCTest сборка всё ещё запускается для диагностики; упаковка требует успеха всех проверок. Unsigned IPA нуждается в подписи. Workflow и публикация в GitHub здесь не запускались.

## Проверки Windows

`python Luma/scripts/check-static.py` не требует сторонних пакетов. Дополнительно из папки версии:

```powershell
python -m pip install --target Luma/.validation-tools/packages -r Luma/scripts/requirements-validation.txt
python Luma/scripts/check-source-grammar.py
python Luma/scripts/check-preserved-sources.py
```

Tree-sitter проверяет грамматику, не типы и не Apple SDK. Результаты — в `Luma/Docs`. Не переносить результаты 98 тестов 0.9.1 на 0.9.2.

## Остальная функциональность

Сохранены интерфейс и тема, дневник, записи, библиотека мелодий, настройки, календарный планировщик и исходники REM-алгоритмов. **В 0.9.1 уже отсутствовали отдельный Watch-клиент и прямые маршруты Watch/оба; REM всю ночь уже был выключен флагом.** В 0.9.2 это не восстановлено и не объявляется работающей функцией. HealthKit остаётся необязательным чтением истории сна.
