# Фактическое состояние — 0.9.3 (19), 12 ноября 2026

## Причина текущей остановки CI

На скриншоте запуска №22 GitHub не выделил hosted runner после нескольких попыток; рядом предупреждения о ёмкости macOS ARM64. Шаги checkout, Swift и Xcode не начались. Это инфраструктурная ошибка до исполнения проекта; по ней нельзя судить о компиляции или работе приложения.

При первоначальной проверке GitHub Status сообщал об инциденте Actions/Pages/Copilot. К завершающей проверке официальный API уже вернул Actions=operational без активных инцидентов; ответ сохранён в `Luma/Docs/github-status-observation.json`. Принадлежность именно запуска №22 этому инциденту без URL и времени не подтверждена.

## Изменено в этой версии

- Основа — полная копия V.0.9.2; новая версия 0.9.3 (19).
- Явно выбран стандартный `macos-15-intel`, с тем же Xcode 26.3.
- В логах первого шага выводятся архитектура runner и путь Developer tools.
- Условия упаковки IPA обновлены для номера 0.9.3 (19). Все проверки обязательны.
- README, AGENTS, CHANGELOG и этот статус обновлены. Инструкция — `Luma/Docs/CI_RUNNER_ISSUE.md`.

## Функциональность сохранена из 0.9.2

Умный будильник и непрямой метод используют обычные локальные уведомления с конечным звуком 4,0 секунды. Сохранены миграция/отмена прежнего AlarmKit, интервалы 10–60 минут, 30-минутная серия, ID и состояние очереди, оригиналы голосов, дневник, интерфейс, конфигурация подписи и все 107 core XCTest / 19 macOS queue-сценариев.

Исходники приложения, тесты и ресурсы сравниваются с 0.9.2 по SHA-256. Они не изменены в рамках исправления CI.

## Проверка и ограничения

Переносимые структурные и YAML/grammar-проверки выполняются в Windows; результаты — `verification.json` и `Luma/Docs/*.json`. Старые результаты отделены от текущих. Нативные Swift-тесты, AVFoundation/queue-harness, Xcode build, подпись и установка **в этой среде не выполнялись**. Новая сборка GitHub из этой папки не отправлялась и не запускалась.

Выбор Intel снимает зависимость от ARM-пула, но не гарантирует выдачу runner во время общего сбоя GitHub. Новый commit/run нужен для применения нового workflow; Re-run старого запуска использует прежний YAML.

Ограничения сигналов прежние: Silent/Focus/сводка могут подавить или задержать звук, Watch могут получить уведомление вместо iPhone, очередь конечна и пополняется при выполнении Luma, после reboot нужен первый unlock. Четыре слышимые секунды на физическом iPhone не подтверждены. Watch-клиент и REM всю ночь уже были удалены/выключены в 0.9.1; эта версия не восстанавливает их.

## Дальнейшая проверка

1. После восстановления GitHub Actions загрузить содержимое V.0.9.3 в корень репозитория новым commit.
2. Убедиться в новом запуске, что runner Intel/X64 и Xcode 26.3, затем дождаться результатов обязательных шагов.
3. Подписать тем же Team и выполнить `Luma/Docs/DEVICE_TESTS.md` на физическом iPhone/Watch.
4. Не объявлять успешную сборку или автоостановку без фактических результатов.

**Готовность к подтверждённому выпуску: нет.** Подготовлен обход ограничения ARM runner; доступность сервиса и работа приложения на устройстве требуют проверки.
