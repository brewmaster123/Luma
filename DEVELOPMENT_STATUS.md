# Фактическое состояние 0.9.6 (22)

Реализованы NightAudio, prearmed AlarmKit Stop, runtime gate/disarm и Watch companion с собственным расписанием. Это изменение архитектуры, а не повторная попытка закончить AlarmKit одним коротким WAV.

Пользователь разрешил тихий фон. Между сигналами играет самостоятельный дождь; он не отправляет вибрацию на часы. Звуки AlarmKit остаются отдельными четырёхсекундными WAV. События Watch — собственные одноразовые локальные оповещения.

Windows: структурные/grammar проверки и Python integrity тесты выполнены; точные числа в verification.json. Нативные XCTest/AVFoundation/queue/build результаты фиксируются только после фактического CI исполнения. Сам факт наличия нового test case не является PASS.

На физическом iPhone/Watch версия 0.9.6 пока не измерялась. Заблокированное состояние теперь имеет реальный источник background runtime, но AlarmKit/звонок/смена аудиомаршрута могут прервать его. Код обрабатывает interruption и снимает очередь при потере runtime; это ещё нужно проверить внешней записью без Xcode debugger.

Force quit/убийство процесса прекращают NightAudio, а системные AlarmKit alarms могут пережить процесс. Гарантии Stop в таком состоянии нет. Пользователь должен завершать ночь кнопкой снятия очереди. После холодного запуска прежняя очередь снимается до нового явного включения фона.

Watch-сигнал не зависит от locked/unlocked iPhone после подтверждённого переноса full plan. Нужны разрешения на Watch, часы на руке и разблокированы; Focus может подавить local cue. Задержку переноса/потерю связи интерфейс показывает ожиданием. Дублирование с собственным AlarmKit mirroring ещё требует проверки.
